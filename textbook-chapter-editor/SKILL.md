# Textbook Chapter Editor — 教材章節編輯 Skill

本 skill 用於處理繁體中文線性代數教材，執行結構化編輯任務。
所有任務共享同一份「章節背景資訊」，因此一律先執行模組0掃描，再執行指定模組。

---

## 執行流程

```
使用者提供章節 + 指定任務
        ↓
  [模組0] 自動掃描章節，推斷背景資訊
        ↓
  呈現推斷結果，等待使用者確認或修改
        ↓
  執行指定模組（1、2、3、4，可組合）
        ↓
  以「局部修改格式」輸出，標明插入或替換位置
```

若使用者沒有指定要執行哪些模組，詢問後再執行。

---

## 模組0 — 章節掃描與背景資訊推斷

讀取使用者提供的章節文字，**自動推斷**以下資訊並條列呈現，讓使用者確認或修改：

```
📋 章節背景資訊（推斷結果，請確認或修改）

- 章號與標題：[例：第八章 特徵值問題]
- 各節清單：
    §8.1 [標題] — [一句話說明主題]
    §8.2 [標題] — [一句話說明主題]
    ...
- 引言結尾的核心問題或意象：[引言末段的核心提問]
- 前一章主題：[依內容提及的概念推斷，如不確定請標示「？」]
- 後一章主題：[同上]
- 本章核心定理或概念（3–5 條）：[從正文中提取]
```

確認後才繼續執行後續模組。若使用者修改了任何欄位，以修改後的版本為準。

## 模組1 — 各節小結

**觸發語**：「加小結」、「任務一」、「section summary」

在每個小節（`##` 或 `###` 層級的 §X.Y）末尾、下一節標題之前，插入小結區塊。

### 格式

```markdown
:::{admonition} §X.Y 小結
:class: tip
[小結內容]
:::
```

### 內容規範

- 用一個核心問題開頭，點出本節試圖回答什麼（「本節回答了……」）
- 用流暢散文（**不用條列**）說明主要結論與邏輯
- 末尾一句點出與下一節的銜接
- 長度 150–250 字，不超過 4 段

### 術語規範（全 skill 通用）

| 項目 | 規範 |
|------|------|
| 行／列 | 依 `references/tc-conventions.md`（行 = column，列 = row）；本 skill 只處理繁體中文教材 |
| 向量符號 | $\mathbf{v}$（粗體小寫） |
| 矩陣符號 | $\mathbf{A}$（粗體大寫） |
| 共軛轉置 | $\mathbf{A}^*$ |
| 章節引用 | §8.1 格式 |
| 禁止 | ASCII art、條列清單 |

### 輸出格式

標明每個小結的插入位置：

```
【插入位置：§8.1 末尾、§8.2 標題之前】

:::{admonition} §8.1 小結
:class: tip
...
:::
```

## 模組2 — 全章散文總結重寫

**觸發語**：「重寫總結」、「任務二」、「chapter summary」

將原有的條列式末節小結，改寫為結構完整的散文，並附 mermaid 知識圖譜。

### 三段結構

**（一）理論脈絡的回顧**
按節次順序，用散文串聯各節核心成果。強調每節如何回答更深的問題，以及各節間的邏輯遞進。

**（二）與前後章的理論聯繫**
說明本章如何承接前章（具體概念橋樑），以及如何鋪墊後章（哪些概念被延伸）。如有跨多章的概念線索，一併指出。

**（三）本章在全書中的地位**
1–2 段：本章解決了什麼問題、開放了什麼問題；這些問題在自然界、工程或資訊科學中的普遍性；讀者帶著本章視角繼續閱讀後有何不同理解。

### 格式要求

- 全部散文，不用條列
- 各部分用 `###` 子標題分隔
- 語氣：學術但不艱澀
- 散文本文約 600–900 字
- 散文之後接知識結構圖譜（見下方）

### 知識結構圖譜（mermaid）規範

在散文末插入：

````markdown
### 知識結構圖譜
```{mermaid}
graph TD
    ...
```
````

**繪圖規則：**

1. 每節 1–3 個節點，全圖節點總數 8–15 個
2. 箭頭方向 = 邏輯依賴：A → B 表示「理解 A 是理解 B 的前提」
3. 必須體現跨節概念銜接
4. 跨章節點用虛線邊 `-.->|承接|` 或 `-.->|鋪墊|`，搭配 `classDef` 標示淡色樣式 `fill:#f5f5f5,stroke:#aaa,stroke-dasharray:5 5`
5. 節點標籤：繁體中文，≤10 字，換行用 `<br/>`，**不可用 `\n`**
6. `subgraph` 分組格式：`subgraph S1["§8.1 節名"]`（ID 為純英數字）
7. **節點 ID 只能用英數字與底線**，不含中文、`§`、空格
8. **不可用 `:::` 行內 class 語法**；樣式一律在圖末用 `classDef` + 獨立 `class 節點ID 樣式類別` 語句
9. 整體流向 `graph TD`（上到下）

### 輸出格式

```
【替換位置：原「X.N 小結」節全文】

### X.N 小結

[散文（一）...]

[散文（二）...]

[散文（三）...]

### 知識結構圖譜
...
```

## 模組3 — 本章結構與學習目標

**觸發語**：「學習目標」、「任務三」、「chapter overview」

在章節引言（歷史回顧）結束後、第一個 §X.1 標題之前，插入導讀區塊。

### 內容結構

1. **開篇銜接**：一句話呼應引言結尾的核心問題，作為進入正文的起點
2. **各節串聯敘述**：依節次，用散文逐節說明——這節要回答什麼、核心概念是什麼、讀完後會得到什麼理解（每節 2–4 句，著重「為什麼學這節」）；各節間用自然語言銜接，避免機械式「接下來……然後……」
3. **結尾一句**：點出讀完整章後讀者對某核心問題的理解將有何轉變，對讀者說話，不用教師手冊語氣

### 風格規範

- 口吻：作者對讀者說話，親切而嚴謹
- 禁止：「本章旨在培養……」「學生應能……」等教師手冊語氣
- 全散文，不用條列，不用 `**步驟N:**` 格式
- 不重複引言的歷史細節，只做最簡短呼應
- 節號（如 **§8.1**）可作為自然定位標記出現
- 全文約 250–400 字

### 格式

```markdown
### 本章結構與學習目標

[散文內容]
```

### 輸出格式

```
【插入位置：引言末尾、§X.1 標題之前】

### 本章結構與學習目標

...
```

## 模組4 — 添加練習模塊

**觸發語**：「加練習」、「新增習題」、「練習模塊」、「添加練習」、「任務四」、「exercise module」

在章節末尾（所有正文與附注之後）插入一個完整的練習區塊。

### 核心原則：練什麼？

練習題**不重複正文已有的例題**，而是聚焦於正文**隱含但未明說**的知識點：

- 正文分開介紹的概念，需要學生**橫向對比或整合**的
- 定理或公式有**邊界條件、反例、極端情形**未被舉例的
- 正文提到某結論「顯然」或「可驗證」但**從未數值演練**的
- 有自然推廣或特殊情形，正文**略而不提**但難度適中的
- 計算步驟正文示範過，但**方向顛倒或條件變化**時的情形

每道題設計前，先在心中問：「這道題考的，學生在正文哪裡找不到直接答案？」若能在正文直接複製答案，該題應改寫或捨棄。

### 題目數量與難度分布

- 共 **3–5 道題**，涵蓋本節至少 **3 個不同的隱含知識點**
- 難度分布：約 **60% 基礎（單概念驗算）、30% 整合（跨視角或跨節）、10% 延伸（開放推導）**
- 每道題可含 **2–4 個子問 (a)(b)(c)(d)**，子問之間有邏輯遞進

### 題目格式（MyST Markdown）

每道題使用 `::::{exercise}` 指令，解答使用 `:::{solution}` 內嵌：

````markdown
::::{exercise} [題目簡短標題]
:label: ex-[章節縮寫]-[主題關鍵字]

[題目敘述。先給出矩陣或情境設定，再逐子問列出要求。]

**(a)** [子問一]

**(b)** [子問二]

...

:::{solution}
:class: dropdown

**(a)** [解答，含關鍵步驟與最終結果。]

**(b)** [解答。]

...
:::
::::
````

### 題目敘述規範

- 設定清楚的**具體矩陣或向量**（帶數字或帶符號均可，視知識點而定）
- 子問之間有**邏輯遞進**：通常從計算 → 觀察 → 推廣
- 不用「試證明」等過重語氣；用「說明」、「驗證」、「找出」、「計算」
- 每道題末不加「（難度：★★）」等標記

### 解答規範

- 每個子問的解答需包含**關鍵計算步驟**，不只給最終答案
- 用 LaTeX 寫出矩陣與等式，保持與正文相同的符號體系
- 若驗算結果與正文某例題吻合，可用「與正文 §X.Y 例 Z 吻合」作簡短交叉參照
- 末尾可用 ✓ 符號表示驗算完成

### 整體輸出格式

````
【插入位置：§X.Y（或整章）末尾，所有正文之後】

---

## 練習

::::{exercise} ...
::::

::::{exercise} ...
::::

...
````

### 品質自查（模組4 專用）

在輸出前逐題確認：

- [ ] 此題考的知識點，在正文中**找不到直接答案**
- [ ] 具體矩陣或情境已給定，學生無需自行假設
- [ ] 子問有邏輯遞進，不是重複同一操作
- [ ] 解答含關鍵步驟，非只有最終數字
- [ ] label 格式為 `ex-[章節]-[關鍵字]`，純英數字與連字號
- [ ] 術語符合全 skill 規範（行／列依 `references/tc-conventions.md`）

## 模組5 — 全書 Label 索引與交叉引用檢查

**觸發語**：「生成 label 索引」、「檢查交叉引用」、「檢查重複 label」、「斷鏈檢查」、「任務五」、「label index」

掃描全書（或指定章節）的 `.md` 與 `.ipynb` 檔案，生成 label 索引（預設 `label_index.md`），
包含三部分：**按章分組的 label 索引表**、**重複 label 檢查**、**斷鏈檢查**。

### 執行方式（優先使用腳本，不要人工掃描）

需 Python 3.10 以上，解析依賴見 `scripts/requirements.txt`。缺少時先確認使用者選用的環境，經同意再安裝：

```bash
python -m pip install -r <本 skill 的目錄>/scripts/requirements.txt
```

缺少依賴時以退出碼 2 停下，不產生報告；腳本不自行安裝。`myst_common.py` 隨 skill 附帶，供後續 CMF-T007 繁簡轉換共用；該任務接入時各自附相同副本並核對位元組。

```bash
python3 <本 skill 的目錄>/scripts/generate_label_index.py \
    chapters/*.md chapters/*.ipynb \
    -o label_index.md
```

- 接受任意數量的 `.md` 與 `.ipynb` 檔案（`.ipynb` 只掃描 markdown cell）
- 若使用者只要求檢查單一章節，僅傳入該章檔案，但**重複 label 與斷鏈檢查
  建議始終傳入全書檔案**，因為交叉引用可能跨章
- 檔案路徑換成自己書稿的實際位置；報告裡的檔名按傳入的路徑顯示，不同目錄的同名檔案可以分開
- 任一檔案讀不到、或不是合法的 notebook 時，腳本報出檔案並以退出碼 1 停下、不寫報告；先修好輸入再跑，不要把部分掃描的結果當成完整檢查

### 腳本能識別的內容

| 項目 | 語法 |
|------|------|
| directive label | `:::{prf:theorem}` 等之後的 `:label: xxx`（含 `::::{exercise}`、` ```{math} `） |
| 標題錨點 | `(sec-xxx)=` |
| 行內方程 label | `$$ ... $$ (eq-xxx)` |
| 交叉引用 | `` {prf:ref}`xxx` ``、`` {ref}`xxx` ``、`` {numref}`xxx` ``、`` {eq}`xxx` ``，含 `` {ref}`文字 <xxx>` `` 形式；directive 標題行裡的引用也收集 |
| 不收集 | 程式碼區塊（含 ```` ```{code-cell} ````）與行內程式碼裡的 label、錨點與引用（它們只是示例）；寫在標題之前的 `(sec-xxx)=` 歸到它所標的標題 |
| 解析範圍 | 使用 markdown-it-py 的 CommonMark、表格與 mdit-py-plugins（colon_fence、dollarmath、front matter、MyST target／role、footnote、amsmath）。塊級只用行號；一般 directive 內文遞迴解析，行內按段落掃描，標題與表格單元格也檢查。YAML 選項塊整段保護，只開放 caption、title、alt、subtitle 四種文字選項；YAML 由完整文字標量產生 token，註解與其餘選項不收引用或粗體候選。無法獨立核對的選項行原樣保留並登記。行內掃描與 text token 差分不一致或定界未配對時，整段原樣保留，逐行列入「需要人工確認的位置」，其餘段落繼續；label、引用與粗體候選仍由 token 收集。專案自訂 directive 的特殊語義仍需人工核對 |
| 已知限制 | directive 的冒號式選項區不轉換，含中文的列進人工確認。 |

### 輸出格式（由腳本自動生成）

```markdown
# 全書 Label 索引

## chapters/ch08.md
| Label | 類型 | 標題 | 章節位置 |
|---|---|---|---|
| `thm-fund-algebra` | 定理 | 代數基本定理 | §8.2 |
...

## 重複 Label 檢查
- ⚠️ `xxx`：檔案A §a.b；檔案B §c.d   （或 ✅ 無重複 label）

## 斷鏈檢查（引用了不存在的 label）
- ⚠️ `xxx` — 引用於 檔案 §a.b        （或 ✅ 所有交叉引用均可解析）
```

### 執行後的回報規範

1. 報告寫入 `-o` 指定的檔案（預設 `label_index.md`）
2. 在回覆中**只摘要問題項**（重複與斷鏈），不要把整個索引表貼進對話
3. 對每個重複 label，提出改名建議（如 `thm-matrix-representation` →
   `thm-matrix-representation-abstract`），並標明需修改的檔案與 §位置；
   改名時提醒同步更新所有引用處
4. 若新章節即將命名 label，可先檢索此索引避免衝突

### Label 命名規範（供新增 label 時參考）

- 前綴對應類型：`thm-`（定理）、`lem-`（引理）、`cor-`（推論）、`def-`（定義）、
  `ex-`（例）、`exer-`（練習）、`eq-`（方程）、`sec-`（標題錨點）、`fig-`（圖）
- 純小寫英數字與連字號，不含中文、底線以外符號
- 全書唯一；跨章同名概念以章號或限定詞區分（如 `-abstract`、`-chap4`）

## 靜態網頁的粗體與互動輸出檢查

輸出前用共用解析層檢查 `.md` 或 `.ipynb` 的 Markdown：

```bash
python <本 skill 的目錄>/scripts/check_bold.py chapters/ch08.md chapters/ch09.ipynb
```

- 粗體若寫成 `**結論。**接著說明`，標點後的 `**` 緊接漢字，CommonMark 可能無法閉合，網頁會顯示星號。把標點移到粗體外：`**結論**。接著說明`。腳本找解析後文字 token 殘留的 `**`，列出檔案、格與所在區塊的起行；退出碼 0 表示沒有候選、1 表示有候選、2 表示輸入／依賴錯誤。逐條判斷是否原本就要顯示星號，不盲目批次替換；程式碼與數學式內的示例不列入。
- ipywidgets（如 Pygwalker）的格若在靜態網頁只剩佔位，為該 code cell 加上 `remove-output` tag，並在格後附靜態截圖與圖注。保留互動程式碼；若尚無截圖，回報缺少的圖，不假稱已補好。以實際靜態建置結果確認佔位消失、圖片與圖注可見。
